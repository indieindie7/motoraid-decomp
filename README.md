# Motor Raid (Sega Model 2A arcade) reverse-engineering notes and symbols

Function names, tools and working notes for **Motor Raid** (Sega AM1, 1997), a bike combat racer on the
Sega Model 2A board. The main CPU is an Intel i960 KB (little-endian, 32-bit). Ghidra has no i960 processor, so this
repository also carries a SLEIGH module for it, written for this project. Same method as
[ducatiworld-decomp](https://github.com/indieindie7/ducatiworld-decomp) and
[segarally-decomp](https://github.com/indieindie7/segarally-decomp).
Non-commercial, done for study and preservation. No ROM data, binaries or decompiled C are in this repository, and
this is not a matching or rebuildable decompilation.

All 2021 functions in the program ROM (plus its fast-RAM copy at `0x200000`) have a name, 0 `FUN_` left; 9 stay
marked `provisional` in their comment.

## How it was named

1. **i960 SLEIGH module** (`sleigh/i960/`, generated by `tools/gen_i960.py` and `tools/gen_cspec.py`; encodings from
   the public MAME `i960dis.cpp`). Checked against MAME's disassembler with `tools/cmpdis.py`: 33872 of 33872
   instructions decoded, 99.97% same mnemonic.
2. **Function discovery**: `tools/seeds.py` (every `call`/`bal` target) and `tools/gaps.py` (start of every
   `ret`-terminated run no function covers), applied by `ghidra/scripts/SetupMotorRaid.java`, which also maps the
   boot-time copy of ROM `0xb0000` to RAM `0x200000`.
3. **Decider** (`tools/m2rules.py`): empty and constant-return bodies, plus hints per function (Model 2A hardware
   blocks touched, float use, strings). 62 names, 768 hints.
4. **Round 1**: the decompile, with hints injected (`tools/injecthints.py`), cut into 14 slices (`tools/slice.py`)
   and named by language-model agents (`ghidra/naming/prompt_r1.txt`). 2031 names.
5. **Round 2**: every provisional, suffixed or "data" name reviewed again (`ghidra/naming/prompt_r2.txt`): 488
   reviewed, 465 confirmed, 16 renamed, 7 unsure. 86 blocks confirmed as data were removed as functions
   (`ghidra/scripts/DeleteFunctions.java`).

Largest groups: `bike_` 257, `hud_` 126, `menu_` 116, `fx_` 94, `pal_` 93, `test_` 90, `cam_` 75, `tile_` 71,
`snd_` 63, `tgp_` 55, `net_` 53.

## Bike physics in short

Unlike a rigid-body sim, a bike is a point mass with a heading. Lean and pitch are smoothed from two wheel ground
samples, and speed comes from arcade friction, drag and boost terms. Each frame `bike_UpdatePhysicsFull`
(`0x0020ebd0`) reads the controls, runs the state machine, ground physics (`bike_UpdateGroundPhysics` `0x00210900`:
gravity per rider type, suspension target, damping, friction, rolling drag), tyre grip (`bike_CalcTyreForce`
`0x0020a4a0`), engine rpm and auto gear shift, then wall and bike-to-bike collisions. Vector maths runs on the
coprocessor port at `0x880000`. Addresses and constants are in `NOTES.md`, "Bike physics map"; the constants are as
read from the decompile and not yet hand-checked.

## Use

Bring your own ROM set. Join the two program ROMs (low half `epr-20007.12`, high half `epr-20008.13`) with
`tools/interleave.py`. Copy `sleigh/i960` to `<ghidra>/Ghidra/Processors/i960` and compile the `.slaspec` with
Ghidra's `support/sleigh`. Import the image as raw `i960:LE:32:default` at `0`, run `SetupMotorRaid.java`, then
`ApplyNames.java ghidra/hand_0.txt` (the name importer from
[scorcher-decomp](https://github.com/indieindie7/scorcher-decomp)).
